# Устройство проекта

Проект использует C++17 и Qt 6.2+. Классы разделены по ответственности; компоненты взаимодействуют через сигналы Qt и небольшие типизированные интерфейсы.

| Компонент | Ответственность |
| --- | --- |
| `EditorDocument` (`src/core`) | Путь текущего файла, состояние документа, чтение UTF-8 и сохранение через `QSaveFile`. Не создаёт виджеты и не показывает диалоги. |
| `Diagnostic` (`src/core`) | Значение с координатами и сообщением. Проверяет наличие позиции для перехода. |
| `CodeEditor` | Ввод, нумерация строк, подсветка, переход к координатам. О перетаскивании файла сообщает сигналом `fileOpenRequested`. |
| `SyntaxHighlighter` | Фиксированный набор правил подсветки текста. |
| `DiagnosticsPanel` | Отображение сообщений и сигнал `diagnosticActivated`. Координаты берутся из объектов `Diagnostic`, а не из текста ячеек. |
| `HelpContent` | Неизменяемый каталог разделов `TextSection`, справочные материалы и демонстрационный текст. |
| `MainWindow` | Сборка интерфейса, подключение компонентов, выбор файлов и подтверждение действий пользователя. |

## Владение и состояние

Виджетами, действиями и другими дочерними `QObject` владеют их родители Qt. Локальные файловые объекты и диалоги освобождаются при выходе из области видимости.

Редактор владеет своим `QTextDocument`. `EditorDocument` получает ссылку на этот существующий документ и привязывается к его времени жизни через родителя `QObject`. Так у текста и признака изменений остаётся один источник состояния, а история отмены и подсветка работают с тем же документом.

Файловые операции возвращают `std::optional<DocumentError>`: пустое значение означает успех, объект ошибки содержит тип операции, путь и пояснение. Неудачное открытие сохраняет текст, путь и историю отмены. Неудачное сохранение сохраняет путь и признак изменений; они обновляются только после успешного `QSaveFile::commit()`.

Сигнал `contentsReplaced` используется для очистки результатов и возврата курсора в начало при открытии файла, создании документа и загрузке примера. Обычное редактирование этих действий не вызывает.

## Сборка и проверки

`ifelse_core` содержит логику документа и зависит от Qt Gui для `QTextDocument`. `ifelse_gui` содержит виджеты и зависит от `ifelse_core` и Qt Widgets. Исполняемый файл `IfElseAnalyzer` связывает компоненты. Версия генерируется из `project(... VERSION ...)` в CMake и передаётся в сведения о приложении.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build --parallel
cmake -E chdir build ctest -C Debug --output-on-failure
```

Для тестов нужен Qt Test. `test_document` проверяет файловые операции, состояние и историю отмены. `test_gui` проверяет навигацию, удаление текста, drag-and-drop, диагностику, F5 и подтверждение замены документа. CTest задаёт `QT_QPA_PLATFORM=offscreen`, поэтому отдельный дисплей не нужен.

Для GCC/Clang включены `-Wall -Wextra -Wpedantic`, для MSVC — `/W4 /permissive- /utf-8`. Стандарт C++ задаётся свойствами целей CMake и распространяется через их зависимости.
